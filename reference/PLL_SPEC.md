# PLL一覧から手順を選んで画像を作る：仕様

## ゴール
メガミンクスのPLL（全151ケース）から1つ選ぶと、その手順（AUF込み）が Algorithm 入力欄に入り、
そのPLLのケース画像がすぐに作られるようにする。

## 前提（既存の仕組み）
- 手順入力は `js/alg-input.js`。入力欄 `#alg` の値を `MegaminxState.applyAlg()` で計算し、
  `uface0..10` / `sface1..15` に書き込んで `imageChange()` で再描画する
- 種類は `alg`（Algorithm to apply）/ `case`（Algorithm to solve case）/ `state`（Defines the puzzle state）
- 記法は `megaminx-state.js` の先頭コメントのとおり（`U F R L BR BL DR DL DBR DBL B D y`、`'`、`2`、括弧）

## 元データ：`pll/algs_info.json`
```json
"1": {
  "name": "A1+",
  "group": "A",
  "algset": "PLL",
  "s": "R U R' U2 R' U' R U' R U' R' U2 R' U R",
  "a": "F' R' F R U' R' F' R2 U R' U' R' F R"
}
```
- `name`：ケース名（151件、23グループ A〜Z）
- `group`：グループ名
- `s`：揃った状態から適用するとそのケースになる手順（R・Uのみ）。**ケースの正しい向きの基準**として使う
- `a`：そのケースを解く手順（1本の文字列。元のトレーナーのデータでは配列だったが、各ケース1本に絞ったので文字列にした）
- 現在の内容：トレーナーの書き出し `customAlgsExport.json`（83ケース）にあるケースは、`a`・`s` ともその内容で置き換えた。書き出しに無い68ケースは元のまま。`J3+` は利用者が手順を選んだ

### 記法の違い
| 元データ | このアプリ |
|---|---|
| `Br` | `BR` |
| `Dfr` | `DR` |
| `x` / `x'` | 未対応 |

- 生成スクリプトで `Br`・`Dfr` を読み替える
- 現在の元データでは、`Br`・`Dfr` を読み替えた手順はすべて `s` のケースを解けることを確認済み（前後のAUFと全体回転を補えば揃う）
- `x` / `x'` を含む手順は扱えないので、`a` に使わない

## 手順に付けるAUF
元データの手順はそのままだと前後に U がずれる（`s` の状態に適用しても揃わないものが多い）。
そこで収録する手順は次の形にする:

```
[前AUF] 元の手順 [後AUF] [全体回転]
```
- 前AUF・後AUF：`U` `U2` `U2'` `U'` のいずれか、または無し
- 全体回転：手順中の `y` で向きが変わった分を戻す `y` / `y2` / `y2'` / `y'`（必要なときだけ）
- 条件：`s` の状態にこの手順を適用すると、完全に揃った状態（向きも元どおり）になること
  - これにより `case` 表示の画像は `s` を適用した状態と一致する
- 候補が複数あるときは、前AUFなし → 手数が少ないもの を優先する

AUF・全体回転は画面表示のたびに計算せず、下記のスクリプトで事前に求めてデータファイルに書き出す。

## データファイル（生成）
- 生成スクリプト `tools/build-pll-data.js`（node で実行）：`pll/algs_info.json` を読み、記法の読み替えとAUFの付加を行って `js/pll-data.js` を書き出す
- 次の場合はエラーで止め、該当するケース名を表示する（`js/pll-data.js` は書き出さない）
  - `a` が文字列でない
  - 手順が解釈できない（`x` を含むなど）
  - AUF・全体回転を補っても `s` のケースを解けない
- `js/pll-data.js` は手で編集しない。ブラウザでは `window.PLL_DATA`、node では `module.exports`
- 形式（元データの順番を保つ）
  ```js
  [
    { name: 'A1+', group: 'A', alg: "U' F' R' F R U' R' F' R2 U R' U' R' F R U2", setup: "R U R' ..." },
    ...
  ]
  ```
  （上の手順例は形を示すためのもので、実際のAUFはスクリプトの計算結果による）

## 画面
全151ケースを常に並べると画面を圧迫するので、**1行に収まる2つのセレクト**で選ぶ。

```
PLL  [Group ▼ A ] [Case ▼ A1+ ]
```
- 置き場所：`#algEditor` 内、手順入力欄の上。狭い画面では縦に並ぶ（Bootstrap の `row` / `col-12 col-md-*`）
- **Group**：`-- PLL --`（未選択）と A〜Z の23グループ
- **Case**：選んだグループのケースだけを出す（最大でも I・X の14件程度）。グループ未選択なら無効
- 選択肢はすべて JS でデータから生成する

## 動作
PLLを選んでいる間は、種類に応じて入力欄 `#alg` に入れる手順を変える。どちらでも画像は同じケースになる。

| 種類 | 入力欄に入れる手順 |
|---|---|
| `alg`（Algorithm to apply） | `setup`（元データの `s`） |
| `case`（Algorithm to solve case） | `alg`（元データの `a`、AUF込み） |
| `state`（Defines the puzzle state） | 変更しない（入力欄は非表示） |

1. **ケースを選んだとき**（Group を選ぶと、そのグループの先頭ケースを自動で選ぶ）
   - 種類を `case`（Algorithm to solve case）に切り替える（既定）
   - 入力欄に上の表の手順を入れる
   - 配色プリセットは変更しない
   - ファイル名 `#fname` を `pll-<名前>.png`（例：`pll-A1+.png`）にする
   - `update()` で画像を作り直す
2. **PLLを選んだまま種類を切り替えたとき**
   - `alg` ⇔ `case` を切り替えると、入力欄を上の表の手順に差し替える（PLLの選択は保つ）
   - `state` に切り替えたときも選択は保ち、`alg` / `case` に戻したら表の手順を入れ直す
3. **選んだ後の編集**
   - 入力欄・種類・配色はこれまでどおり手で変更できる
   - 入力欄を手で書き換えたら、2つのセレクトを未選択に戻す（表示中の手順とPLL名がずれないように）。種類の切り替えによる差し替えは手での書き換えに含めない
   - Clear ボタンでも未選択に戻す
4. **URLパラメータ**
   - `?pll=<名前>` で、そのケースを選んだ状態で開く。`+` は `%2B` と書く（例：`?pll=A1%2B`）。URLでは `+` が空白になるため、名前の末尾の空白は `+` とみなして探す
   - `?alg=` / `?case=` と同時に指定された場合は `?pll=` を優先する
   - 存在しない名前なら無視する（未選択のまま）

## テスト（`test/pll-data.test.js`、node で実行）
- `js/pll-data.js` が元データの全151ケースを含み、名前が重複していない
- 各ケースについて
  - `alg` と `setup` が `applyAlg()` でエラーにならない
  - `setup` の状態に `alg` を適用すると完全に揃う
  - `alg` を `case` として表示した状態（逆手順を適用）が `setup` を適用した状態と一致する
  - 上面11枚がすべてU色（＝PLLは向きを崩さない）
- `js/pll-data.js` が最新（生成スクリプトを再実行しても変わらない）
