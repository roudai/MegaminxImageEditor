# PLL一覧から手順を選んで画像を作る：仕様

## ゴール
メガミンクスのPLL（全151ケース）から1つ選ぶと、その手順（AUF込み）が Algorithm 入力欄に入り、
そのPLLのケース画像がすぐに作られるようにする。

## 前提（既存の仕組み）
- 手順入力は `js/alg-input.js`。入力欄 `#alg` の値を `MegaminxState.applyAlg()` で計算し、
  `uface0..10` / `sface1..15` に書き込んで `imageChange()` で再描画する
- 種類は `alg`（Algorithm to apply）/ `case`（Algorithm to solve case）/ `state`（Defines the puzzle state）
- 記法は `megaminx-state.js` の先頭コメントのとおり（`U F R L BR BL DR DL DBR DBL B D y`、`'`、`2`、括弧）

## 元データ：`data/pll/algs_info.json`
```json
"1": {
  "name": "A1+",
  "group": "A",
  "algset": "PLL",
  "s": "(U') R U R' U2 R' U' R U' R U' R' U2 R' U R",
  "a": "(U') F' R' F R U' R' F' R2 U R' U' R' F R"
}
```
- `name`：ケース名（151件、23グループ A〜Z）
- `group`：グループ名
- `s`：揃った状態から適用するとそのケースになる手順。Algorithm to apply で入力欄に入る
- `a`：そのケースを解く手順（1本の文字列）。Algorithm to solve case で入力欄に入る
- **AUF はここに直接書く**（下記「AUF」）。生成スクリプトは AUF を足さない
- 経緯：トレーナーの書き出し `customAlgsExport.json`（83ケース）にあるケースは `a`・`s` ともその内容で置き換え、書き出しに無い68ケースは元のまま（`J3+` は利用者が手順を選んだ）。その後、自動計算した AUF を `a`（85件）・`s`（86件）に書き込んだ

### 記法の違い
| 元データ | このアプリ |
|---|---|
| `Br` | `BR` |
| `Dfr` | `DR` |
| `x` / `x'` | 未対応 |

- 生成スクリプトで `Br`・`Dfr` を読み替える
- `x` / `x'` を含む手順は扱えないので、`a` に使わない

## AUF
`a`・`s` は次の形で書く:

```
a = [前AUF] 手順
s = [AUF] setup [AUF]
```
- AUF：`(U)` `(U2)` `(U2')` `(U')` のいずれか（括弧で囲む）、または無し
- **`a` の最後のAUFは一律付けない**。例：`(U') F' R' F R U' R' F' R2 U R' U' R' F R`
- **`a` の最後の持ち替え（`y`）も付けない**。手順中に `y` があって完成後の向きが変わっても（例：H2+・H2-）、揃ったとみなす
  - そのため Algorithm to solve case の表示と生成スクリプトの確認では、手順中の `y` の合計を自動で打ち消す（`MegaminxState.applyAlg` の `cancelRotation`）
- 満たすべき条件（生成スクリプトが確認する）
  - `s` の状態に `a` を適用すると、最後のAUFを除いて揃う（向きも元どおり）
  - `a` を Algorithm to solve case で表示した画像と、`s` を Algorithm to apply で表示した画像が一致する
- `a` の前AUFを変えると solve case の画像が（ケースを U で回した形に）変わるので、`s` のAUFも合わせて直す。`s` の前だけでは合わせられないことがあるため、`s` は後ろにもAUFを書ける。`s` の前後のAUFを付け直せば、`a` の前AUFがどれでも合わせられる（全151ケース×5通りで確認済み）
- 合っていなければ生成スクリプトが直し方の候補を表示する

## データファイル（生成）
- 生成スクリプト `tools/build-pll-data.js`（node で実行）：`data/pll/algs_info.json` を読み、記法を読み替え、上記の条件を確認して `js/pll-data.js` を書き出す
- 次の場合はエラーで止め、ケース名と理由を表示する（`js/pll-data.js` は書き出さない）
  - `a`・`s` が文字列でない
  - 手順が解釈できない（`x` を含むなど）
  - `a` の最後にAUF・持ち替え（`y`）が付いている
  - `a` で `s` のケースが揃わない
  - solve case と apply の画像が一致しない
- AUF の付け直しで直るときは、直し方の候補も表示する
  - 書かれた `a` の前AUFは活かし、`s` の前後のAUFを付け直したものを出す（`a` の最後のAUFだけは外す）
  - `a` の最後のAUF・持ち替え（`y`）は外す。`a` を変えたときだけ「候補 a」も出す
  - 候補が複数あるときは `s` に付けるAUFが少ない → `s` の前にAUFを付けない を優先する
  ```
  data/pll/algs_info.json に問題があります:
    A1+: a で s のケースが揃いません（最後の AUF を除いても揃わない）
      候補 s: (U') R U R' U2 R' U' R U' R U' R' U2 R' U R (U2')
  ```
- `js/pll-data.js` は手で編集しない。ブラウザでは `window.PLL_DATA`、node では `module.exports`
- 形式（元データの順番を保つ。`alg`・`setup` は `a`・`s` を読み替えたもの）
  ```js
  [
    { name: 'A1+', group: 'A', alg: "(U') F' R' F R U' R' F' R2 U R' U' R' F R", setup: "(U') R U R' U2 R' U' ..." },
    ...
  ]
  ```

## 画面
全151ケースを常に並べると画面を圧迫するので、**2つのセレクト**（広い画面では1行に並ぶ）で選ぶ。

```
PLL  [Group ▼ A (3 corner CP) ] [Case ▼ A1+ ] [‹ Prev][Next ›]
```
- 置き場所：`#algEditor` 内、手順入力欄の上。狭い画面（md 未満）では Group・Case・ボタンを1行ずつ縦に並べる（Bootstrap の `row` / `col-12 col-md-*`）
- **Group**：`-- PLL --`（未選択）と A〜Z の23グループ。グループの特徴を括弧付きで添える（例：`A (3 corner CP)`。一覧は `js/case-groups.js` の `pll`）
- **Case**：選んだグループのケースだけを出す（最大でも I・X の14件程度）。グループ未選択なら無効
- **‹ Prev / Next ›**：データの並び順（A1+ → A1- → … → Z3）で前後のケースを選ぶ。グループをまたいで移動し、端では反対の端に回る。未選択のときは Next で先頭、Prev で末尾を選ぶ
- 選択肢はすべて JS でデータから生成する

## 動作
PLLを選んでいる間は、種類に応じて入力欄 `#alg` に入れる手順を変える。どちらでも画像は同じケースになる。

| 種類 | 入力欄に入れる手順 |
|---|---|
| `alg`（Algorithm to apply） | `setup`（元データの `s`。必要なら前後にAUF付き） |
| `case`（Algorithm to solve case） | `alg`（元データの `a`。必要なら前にAUF、最後のAUFは無し） |
| `state`（Defines the puzzle state） | 変更しない（入力欄は非表示） |

1. **ケースを選んだとき**（Group を選ぶと、そのグループの先頭ケースを自動で選ぶ）
   - 未選択の状態から選んだときは、種類を `case`（Algorithm to solve case）に切り替える（既定）
   - PLLを選んだまま別のPLLに変えたときは、種類をそのままにする（`alg` なら `alg` のまま）
   - 入力欄に上の表の手順を入れる
   - 配色プリセットは変更しない
   - ファイル名 `#fname` を `pll-<名前>.png`（例：`pll-A1+.png`）にする
   - `update()` で画像を作り直す
2. **PLLを選んだまま種類を切り替えたとき**
   - `alg` ⇔ `case` を切り替えると、入力欄を上の表の手順に差し替える（PLLの選択は保つ）
   - `state` に切り替えたときも選択は保ち、`alg` / `case` に戻したら表の手順を入れ直す
3. **選んだ後の編集**
   - 入力欄・種類・配色はこれまでどおり手で変更できる
   - 入力欄を手で書き換えても選択は外さない（自分の手順として保存できるように。「自分の手順」の節）
   - Clear ボタンでは未選択に戻す
4. **URLパラメータ**
   - `?pll=<名前>` で、そのケースを選んだ状態で開く。`+` は `%2B` と書く（例：`?pll=A1%2B`）。URLでは `+` が空白になるため、名前の末尾の空白は `+` とみなして探す
   - `?alg=` / `?case=` と同時に指定された場合は `?pll=` を優先する
   - 存在しない名前なら無視する（未選択のまま）

## 自分の手順（PLL・OLL 共通）
- 自分の手順は **Algorithm 入力欄そのもの**を書き換えて保存する（専用の欄は置かない）
  - ケースを選んでいる間は、入力欄を手で書き換えても（記号ボタンでも）選択を外さない。今の手順と違えば「編集中」と出す。画像はこれまでどおりすぐ描き直す
  - 入力欄の下の行に「ケース名 · 既定 / カスタム（· 編集中）」と **保存**・**既定に戻す** を出す。ケースを選んでいないときは中身を隠す（行の高さはいつも確保して、下のレイアウトをずらさない）
  - **保存**（または入力欄で Enter）：「この手順で揃う状態」で、編集中のときだけ押せる。「手順を回した状態」では入力欄が setup なので押せず、ツールチップで切り替えを案内する。確かめてから保存し、入力欄と画像を保存した手順で描き直す。だめならメッセージの行にエラーを出し、保存しない
  - **既定に戻す**：自分の手順を消して既定に戻す（自分の手順があるときだけ押せる）
  - 保存・既定に戻すのあとは、メッセージの右に **元に戻す** を出す。押すとその操作の前の状態（前の自分の手順、または既定）に戻す。間違って押しても戻せるように。別のケースを選ぶ・書き換える・種類を切り替えるなどでメッセージが変わると消える
  - 前へ / 次へ・別のケースを選ぶ・種類を切り替えると、編集中の内容は捨ててそのケースの手順を入れる。「クリア」は選択も外す
  - メッセージは1行分の高さをいつも確保し、長いときは省略する（全文はマウスを乗せると出る）
- 確かめる内容（`js/custom-algs.js` の `validate`。確認処理は生成スクリプトと共通の `js/case-check.js`）
  1. 記号を正しい表記に書き直す（大文字・小文字は区別しないので `br` → `BR`、`Y` → `y`。`Dfr` → `DR` なども）。読めなければ `Invalid move: …`
  2. 最後の AUF・持ち替え y は外す（`Removed the final AUF / rotation.` と知らせる）。先頭の括弧の無い AUF は `(U2)` のように括弧で書き直す
  3. 既定の setup の前後に AUF を付け直し（PLL は 5×5 通り、OLL は最後の AUF だけ）、生成スクリプトと同じ確認を通る setup を探す。見つかればそれを apply 用の setup として保存する
  4. 見つからなければ `This algorithm does not solve J3+.`。ほかのケースなら解ける場合は `(it solves C2+)` と添える
  - 既定の手順と同じ回し方（空白・括弧・`R2'` と `R3` のような書き方の違いは同じとみなす）なら自分の手順としては保存せず、自分の手順があれば消して既定に戻す（自分の手順が無かったときは「既定の手順と同じです。」、あったときは「既定の手順に戻しました。」と知らせ、元に戻せる）
- 保存：localStorage の `megaminx-image-editor:custom-algs`（`{ pll: { "J3+": { alg, setup } }, oll: { ... } }`）。読み込むときに確認し、合わない値は無視して既定を使う
- 一覧ページ（手順・画像・一括ダウンロード）も自分の手順を使い、名前の横に `custom` の印を付ける

## 一括ダウンロード
- 一覧ページ（`pll.html`）の見出しの下の **ZIP でダウンロード**（Download ZIP） で、全151ケースの画像を1つの zip（`megaminx-pll.zip`）にまとめてダウンロードする（エディタには置かない）
  - パソコン向けの機能なので、狭い画面（md 未満、幅 768px 未満）では表示しない（Bootstrap の `d-none d-md-inline-block`）
- 各ケースは **solve case**（`alg` の逆手順を適用し、持ち替え y の合計を打ち消す）の状態で描く
- 配色は一覧に表示している色と同じ。Image Size（100〜1000、無ければ 200）・Body Color・Background はエディタで保存した設定を使う（ボタンを押した時点で読み直す）
- ファイル名は個別ダウンロードと同じ `pll-<名前>.png`（例：`pll-A1+.png`）。フォルダには分けず、データの並び順で入れる
- zip は `js/zip-store.js` で作る。外部ライブラリは使わず、PNG はすでに圧縮されているので無圧縮（store）で格納する。ファイル名は UTF-8
- 作成中はボタンを無効にし、`Creating... 37/151` のように進み具合を出す

## 一覧ページ（`pll.html`）
- 全151ケースの画像・名前・手順（`alg`）を、グループごとに見出し（例：`A (3 corner CP)`）を付けて並べる
- 上部にグループのボタン（A〜Z）を置く。押すとそのグループだけを表示する（複数選べる。もう一度押すと外す。1つも選んでいなければすべて）。下に「選択を解除」。選んだものは `list-filter` の `pllGroups`（覚える順では `pllStages`）に保存する。選んだボタンはカードが無くても隠さない（外せるように）
- 画像は solve case の状態。配色と Body Color はエディタで保存した設定（localStorage）を使う。OLL 配色のときは OLL を選ぶ前の配色（`beforeOll`）、それも無いときは Standard
- ケースをクリックすると、そのケースを選んだ状態でエディタ（`./?pll=<名前>`）を開く。保存した配色が OLL 配色のときは、エディタでも Standard で表示する（一覧と同じ色）
- エディタのナビバーに `PLL`・`OLL`（一覧ページ。以前は「PLL一覧」「PLL List」）、一覧ページのナビバーに `Editor` ともう一方の一覧へのリンクを置く
- 並べる列の数は画面幅に合わせる（スマホ2列〜PC6列）
- **習得状況**（PLL・OLL 共通）
  - 各カードの右上の丸いバッジをタップすると、未着手 → 練習中 → 覚えた → 未着手 の順に切り替わる（押せる範囲は 32px）。カードのそれ以外の場所はエディタを開く
  - 見た目：未着手は薄い枠の白い丸、練習中は琥珀色の丸と進捗リング（薄い円の上に 3/4 の弧）のアイコン、覚えたは緑の丸とチェック。カードの枠も練習中は淡い琥珀、覚えたは淡い緑にする。切り替えたときに丸が少し弾むアニメーション（動きを減らす設定では無し）
  - 上部に積み上げの進捗バー（緑＝覚えた、琥珀＝練習中）と件数（`3 learned · 1 learning · 147 to learn`）
  - その下の絞り込みチップ（All / To learn / Learning / Learned、それぞれ件数付き）で、その状態のカードだけを表示する。カードが無いグループは見出しとボタンごと隠し、1枚も無ければ「No cases with this status.」を出す
    - 絞り込み中に状態を変えたカードはすぐには消さない（チップを押し直したときに反映）。件数・バーはすぐ更新する
  - 絞り込みチップの右に「すべて未習得に戻す」（目立たない小さなリンク。習得状況が1つも無いときは出さない）。範囲（No Dot / Dot）・グループの選択に関係なく、その種類（PLL / OLL）のケースすべてが対象
    - 押すとすぐには戻さず、「PLL のすべてのケースを未習得に戻しますか？（習得済み n・練習中 m が消えます）」と「未習得に戻す」「キャンセル」を出す（ブラウザの確認ダイアログは使わない。最初のフォーカスはキャンセル）
    - 戻したあとは「n ケースを未習得に戻しました。 元に戻す」。元に戻すと、そのあとに付けた習得状況は残したまま、消したものを戻す。カードの丸を1つ押すと「元に戻す」は消える
    - 消すのは習得状況だけ（練習の記録・最近のタイムは消さない）
  - 各グループの見出しの右に「覚えた数 / 全体」。全部覚えたグループは数字とボタンを緑にする
  - 保存：localStorage の `megaminx-image-editor:progress`（`{ pll: { "A1+": "learned", ... }, oll: { ... } }`。未着手（表示名 To learn、保存する値は `new`）は保存しない）。選んだ絞り込みは `megaminx-image-editor:list-filter` に PLL・OLL 別に保存する
  - 見た目は `css/cases.css`（一覧ページ共通）
- 描画は `js/megaminx-draw.js`（入力欄に依存しない描画。エディタの `megaminx.js` もこれを使う）、グループ名は `js/case-groups.js`（エディタと共通）、ページの処理は `js/cases.js`

- 段階の短い名前は、中のケースの +/− を除いた名前の文字と番号の範囲（F1、A1–2、E1–3、D、F2–5、K2 …。`js/case-sections.js` の `stageLabel`）
- 一覧・練習で「グループ順 / 覚える順」を切り替えられる（PLL だけ。区切りは `js/case-sections.js` の `CaseSections.list`）。選んだ並びは `list-filter` の `pllOrder`（`'learn'` / `'group'`）に保存し、一覧と練習で共通
  - 一覧：覚える順では、グループの見出しの代わりに段階の見出し（「2. A1–2」と覚えた数 / 全体）で並べ、段階の中も覚える順。上のグループのボタンも段階（F1、A1–2 …）になり、押すとその段階だけを表示する（選択はグループ順と別に保存）。カードは作り直さず入れ直す
  - 練習：グループを選ぶ欄の上に切り替えを置く。覚える順では、ボタンが段階（F1、A1–2 …）になり（欄の名前は日本語では「グループ」のまま、英語では Stages）、選んだ段階の中からランダムに出題する。選んだ段階は `practice.groups['pll-stage']`（段階の番号）に保存する（グループの選択 `groups.pll` とは別に残る）
