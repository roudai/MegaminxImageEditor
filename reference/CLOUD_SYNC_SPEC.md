# ログインとクラウド保存の仕様

## 目的
配色・画像の設定、習得状況、一覧の絞り込み、自分の手順、言語を、ログインしたアカウントに保存し、どの端末・ブラウザでも同じ状態で使えるようにする。
ログインしなくても今までどおりブラウザ（localStorage）だけで使える。

## 構成
- サイトは GitHub Pages（静的ページ）のまま。Firebase（Authentication + Firestore）をブラウザの JS から直接使う（SDK は gstatic の CDN から ES モジュールで読み込む。バージョン固定）
- ログイン：Google / Facebook / GitHub（ポップアップ。メニューもこの順）
- 保存先：Firestore の `users/{uid}/apps/megaminx-image-editor` の1文書 `{ json, savedAt }`。`json` は下の snapshot を JSON にした文字列
  - PLL・OLL の練習の記録（`practice.log`。各最大 10000 件、約 90 万文字ずつ）は 1 文書（50 万文字未満）に入らないので、種類ごとの文書 `users/{uid}/apps/megaminx-image-editor-log-pll`・`-log-oll`（同じ `{ json, savedAt }`）に分ける（`Store.toCloud`・`fromCloud`）
    - 種類ごとの文書の `json` は `{ rows: [[日時, ケース, タイム（null＝解けなかった）, 判定（0 未習得・1 練習中・2 習得済み）, 1（ヒントを見たときだけ）], …] }`（新しい順。1 件 約 30 文字で 10000 件 約 31 万文字。48 万文字を超えるときは古い記録を捨てる）
    - 本体の `json` は記録を抜いた snapshot に `logsSplit: true` を付けたもの（ソルブの記録 `practice.full.log` は本体のまま）。読むときは `logsSplit` があれば種類ごとの文書の記録を戻し、無ければ（以前の形・古いページが書いた本体）本体の記録をそのまま使う
    - 書くときは、中身が変わった種類ごとの文書を先に書いてから本体を書く（1 回の練習で書くのは本体とその種類の文書だけ）
    - 種類ごとの文書に書けなかったとき（Firebase コンソールのルールが古いなど）は、記録を本体に入れた以前の形（PLL・OLL 合わせて最新 2000 件）で本体だけ書き、保存の状態はエラーにする（ほかの変更は失わない）
- 同じ Firebase プロジェクトで、ほかのアプリ（別リポジトリの VisualCube Editor など）も同じアカウントで使う。各アプリは `users/{uid}/apps/<アプリ名>` に保存し、互いの保存先はぶつからない
  - ほかのアプリも同じ形（`{ json, savedAt }`）で保存すれば、`firestore.rules` は変えなくてよい
  - GitHub Pages の同じドメイン（`roudai.github.io`）に置くアプリは localStorage を共有するので、ほかのアプリは別のキーの頭（`megaminx-image-editor:` 以外）を使う
- `firestore.rules`：本人の `users/{uid}/apps/{アプリ名}` だけ読み書きでき、中身は `json`（50万文字未満の文字列）と `savedAt` だけ（プロジェクト共通のルール）。作る・書き換えるのはルールの `appIds()` に書いたアプリ名（`megaminx-image-editor`・`visualcube-editor`）と、その練習の記録の文書 `<アプリ名>-log-<種類>`（種類は英小文字・数字の 1〜12 文字。`logDoc()`。VisualCube Editor も同じ形で記録を分ける）だけ。種類を増やしてもルールは変えなくてよい。アプリを増やしたら `appIds()` と `logDoc()` の両方に名前を足して Firebase コンソールに貼り直す

## 保存の窓口（`js/store.js`）
- エディタ・一覧ページの保存はすべて `Store.get(name)` / `Store.set(name, value)` を通す（localStorage のキーは `megaminx-image-editor:<name>`。今までと同じ形式なので既存のデータはそのまま読める）
- 名前：`settings`（配色・画像の設定）、`progress`（習得状況）、`list-filter`（一覧の絞り込み）、`custom-algs`（自分の手順）、`lang`（言語）、`practice`（練習）、`titles`（取ったバッジ・表示する称号・練習の累計。`js/titles.js`）
- `set` は値が変わったときだけ、名前ごとの更新時刻（`megaminx-image-editor:updated`）を記録し、`store-change` を通知する
- `snapshot()` = `{ data: { name: value }, updated: { name: 時刻 } }`

## ログインしたときの合わせ方（`Store.resolveLogin`）
- 合算はしない（以前は、ログインせずに使った手元の内容をアカウントと合わせていたが、練習の記録は新しく更新された方を丸ごと使うため、ログイン前に数件練習しただけでアカウントの記録が消えることがあった）
- 手元のデータがどのアカウントのものかを `megaminx-image-editor:synced-uid` に、ログインしたままかを `megaminx-image-editor:session`（ログイン中 `in`、ログアウトの状態が分かったら `out`）に覚えておき、次のように決める
  - **新しくログインした**（`session` が `out`）：
    - アカウントにデータがあれば、アカウントの内容で手元を上書きする。ログイン前にこのブラウザで使った内容（習得状況・練習の記録など）は捨てる
    - アカウントが空なら（初めてのログイン・アカウントを削除して作り直した）、手元の内容をそのままアカウントに入れる。ただし手元が別のアカウントのもの（`synced-uid` が別）なら持ち込まず初期状態
  - **ログインしたままページを開いた**（`session` が `out` でなく、`synced-uid` が同じ）：下の `Store.merge`（名前ごとに新しい方。まだクラウドに書けていなかった手元の変更を失わない）
  - どれも言語（`lang`）は手元のものを残す
  - `session` が無い（この仕組みより前からログインしている）ときは、ログインしたままとして扱う。ログアウトの状態でページを開けば `out` になる
- 捨てた内容（習得状況・自分の手順・練習の記録・取ったバッジのどれかが手元にあり、アカウントと違う。`Store.discardsLocal`。練習の記録は日時ごとに、秒・判定・ヒント・ペナルティを比べる）があれば、読み直したあとのページの下に知らせを出し（練習ページのバッジの知らせと同じ形で、出るときに少し大きくなって戻る。`.site-toast`。× か 10 秒で閉じる）、「アカウントのデータを読み込みました。ログインする前にこのブラウザで使った内容は、アカウントのデータに置き換えました。」と知らせる（`sessionStorage` の `megaminx-image-editor:login-notice`）
- ログアウトのボタン：まだクラウドに書いていない変更を書いてからログアウトし、このブラウザのデータ（`Store` の全データ。言語だけ残す）を消して、ページを読み直す。読み直したあとは画面の下に「ログアウトしました。このブラウザのデータは消しました（アカウントには残っています）。」と知らせる
  - 書けなかったとき（オフラインで 15 秒以内に書けない・ログインの同期の途中）はログアウトせず、メニューに「最新の変更をアカウントに保存できなかったので、ログアウトしていません。…」と出す（消すと失うため）。記録を種類ごとの文書に書けず本体だけに書けたときは続ける
  - ページを開いたときの同期が失敗していたとき（`ready` が false のまま）は、まずログインの同期を読み直しなしでやり直す（15 秒まで）。できたら普段どおり書いてログアウトし、データを消す。やり直しても失敗したら（上限を超えた文書など、原因が続くもの）、ログアウトはするがこのブラウザのデータは消さず、`session` を `kept` にして、画面の下に「ログアウトしました。最新の変更をアカウントに保存できなかったので、このブラウザのデータは消さずに残しています。…」と知らせる。`kept` はログアウトの状態が分かっても `out` にしないので、次に同じアカウントで入るとログインしたままとして合わせる（保存できなかった変更を失わない）。別のアカウントなら持ち主が違うので持ち込まない
  - 同じブラウザのほかのタブには `megaminx-image-editor:signed-out-at` の `storage` イベントで伝え、すぐクラウドへの書き込みをやめて（`ready` を false、まとめて書く予定を消す）、読み直して空にする（画面に残っている古いデータを書き戻さないように）
  - ログインの期限切れ・ほかのタブでのログアウト・アカウントの削除など、ボタンを通らないログアウトではデータを消さない（アカウントの削除は、消すかを確認で選ぶ）
  - 持ち主（`synced-uid`）は残す。次のログインは新しいログインとして、上の決め方でアカウントの内容を読み込む

## 合わせ方（`Store.merge`）
ログインしたままページを開いたときと、クラウドに書く前に同じアカウントの別の端末が書いていたと分かったときに使う（ログインしたときの上書きとは別）。
- 名前ごとに更新時刻の新しい方を使う（片方にしか無い名前は残す）
- `practice` は、両方にあれば練習の記録を合わせる（`mergePractice`。2 台で練習したときや、古いデータのままの端末で開いたときに、もう片方の記録を消さないように）
  - PLL・OLL の記録（`practice.log`）とソルブの記録（`practice.full.log`）：両方の記録を日時で 1 つにする（同じ日時は新しい方のもの）。消した記録の印（`removed`：種類ごとの日時の一覧、`cleared`：種類の記録をすべて消し、消した記録が `removed` に入りきらない（1000 件より多い）ときの日時。それ以前の記録はすべて消したもの。入りきるときは 1 件ずつ `removed` に入れるので、この端末に無かった別の端末の記録は消えない）があるものは除き、種類ごとの上限（PLL・OLL 各 10000 件、ソルブ 2000 件）で切る
  - 消した記録の印は `Store.set('practice', …)` が前の値との違いから付ける（`Store.withTombstones`。個別・選択の削除、練習の結果の「取り消す」。上限で押し出された古い記録には付けない。「元に戻す」で戻したら外す。種類ごとに新しい 1000 件まで）。合わせるときは両方の印を合わせる
  - ケースごとの最近のタイム（`practice.times`）：合わせた記録から作り直す（ヒントなし・解けた回の新しい順に 10 回）。記録の方が少ないケース（記録を残す前の古いタイムなど）は新しい方のものを残す
  - それ以外（練習の設定・記録のページの表示など）は新しい方
- `progress`（習得状況）・`custom-algs`（自分の手順）は、両方にあればケースごとに、あとで変えた方を使う（`mergeCases`。2 台で練習・習得状況を変えたときに、片方の変更が消えないように）
  - 変えた時刻は `Store.set` が前の値との違いから、ケースごとに `_at: { pll: { 'A1+': 時刻 }, oll: { … } }` に付ける（`Store.withCaseStamps`）。未習得に戻した・既定の手順に戻した（値を消した）ケースにも付けるので、「すべて未習得に戻す」をした方があとなら、もう片方の古い習得済みで戻ってこない
  - 時刻が無いケース（この仕組みより前のデータ）は、新しく更新された方の値を使う（以前と同じ）
  - 読む側（`progress.js`・`titles.js`・`custom-algs.js` など）は `pll`・`oll` だけを見るので、`_at` は気にしなくてよい
- `titles` は、両方にあればいつも取ったバッジ（`earned`）を合わせる（別の端末で取ったバッジを消さない。日時は早い方）。表示する称号（`shown`）は新しい方。練習の累計（`stats`）は回数・日数・最長の連続は大きい方、最後に練習した日と連続の日数は新しい日の方、「すべて」で出会ったケース（`met`）は和集合。バッジの一覧を見た日時（`seenAt`）は遅い方。外したバッジ（`revoked`。記録を削除して条件を満たさなくなったもの）は遅い方で、それより前に取った `earned` は合わせない（reference/PRACTICE_SPEC.md「判定し直し」）
- `Store.merge` の union（習得状況と自分の手順をケースごとに合わせる）は、ログインのときにはもう使わない

## 動き（`js/cloud-sync.js`）
- `js/firebase-config.js` の `window.FIREBASE_CONFIG` が `null`、または SDK を読み込めないときは何もしない（ログインのボタンも出さない）
- ログインしたとき・ログイン中にページを開いたとき：クラウドを読み → 上の決め方で手元に反映する内容を決め → 両方に書く。手元の内容が変わったらページを1回読み直して画面に反映する
- ログイン中：`store-change` を受けて 1.5 秒まとめてからクラウドに書く。ページを離れる（非表示になる）ときは待たずに書く
- ログインの同期ができて session を `in` にしたら、`Titles.update()`（ログインした時点の記録で条件を満たすバッジを付ける）をしてから `window` に `account-change` を出す。ログアウトの状態が分かったときも出す（記録のページが称号とバッジの欄を出し直す。称号とバッジはログイン中だけ）
  - 書く前に本体の文書を読み、最後に書いた（読んだ）中身と違えば、同じアカウントの別の端末が書いたので、クラウドを読んで `Store.merge` で手元と合わせてから書く（手元も合わせた内容にする。画面は次に開いたときに反映）。書き込みは 1 つずつ順番に
  - 手元が言語だけのときは書かない（ログイン中にそうなるのは、ほかのタブでログアウトしてデータを消した直後だけ。アカウントを空で上書きしないように）
- 別の端末で変えた内容は、次にページを開いたときに反映される
- ログアウトのボタンでは、上のとおりこのブラウザのデータを消す

## 画面（3ページ共通のナビバー）
- ログイン前：言語の切り替えの右に、人のアイコン付きの濃い色のボタン **ログイン / Sign in**（角の丸い四角。マウスを乗せると少し浮く）。押すと Google・Facebook・GitHub のロゴ付きの「Google でログイン」「Facebook でログイン」「GitHub でログイン」のメニュー（よく使われる順）
- ログイン中：ナビバーにはアイコン（写真、無ければ名前の頭文字の丸）だけを出し、右下の小さな点で保存の状態を示す（緑＝保存済み、琥珀＝保存中で点滅、赤＝エラー。マウスを乗せると文で出る）
  - アイコンの右上に、ログインに使ったサービス（Google / GitHub / Facebook）のロゴを小さく出す。マウスを乗せると「Google でログイン中 · アカウントに保存済み」のように出る
  - アイコンを押すとメニュー：大きめのアイコン・名前・メールアドレス・「（ロゴ）GitHub でログイン中」、称号の札と、記録のページのバッジの一覧へのリンク（reference/PRACTICE_SPEC.md「称号とバッジ」）、保存の状態（失敗したときはエラーの種類も）、**ログアウト**
- Facebook のプロフィール写真：Firebase が受け取る写真の URL はアクセストークンが無いと Facebook の既定の人型になるので、そのままは使わない。Facebook でログインした直後に、そのときのトークンで Graph API（`/me/picture`）から本人の写真の URL を受け取り、Firebase のプロフィールに保存する（トークンは保存しない）。写真の URL は Facebook 側で期限が切れるので、読めなくなったら頭文字の丸にする（次に Facebook でログインしたときに更新される）
- ページを開いたときのちらつきを防ぐ：ログイン状態が分かるまでは「ログイン」ボタンを出さない。前回ログインしていたときは、そのアカウントのアイコン・名前・ログイン方法を `megaminx-image-editor:account-hint` に覚えておき、ログイン状態が分かる前からアイコンを出しておく（分かるまではメニューは開かない。ログアウトしたら消す）
- メニューはメニューの外を押すか Esc で閉じる。ログインできなかったときはメニューの中にエラーを出す
- 同じメールアドレスのログイン方法をつなげる（アカウントのリンク）：Firebase の「同じメールアドレスを使用するアカウントをリンク」では、同じメールで別の方法を使うと `auth/account-exists-with-different-credential` になる（自動ではつながない）。このとき
  - 新しい方法の資格情報（`credentialFromError`）とメールアドレスをメモリに覚え、メニューに「{email} は別のログイン方法で登録されています。前に使った方法でログインすると、{provider} でもログインできるようにつなげます。」と、新しい方法以外のログインのボタンを出す（メールの列挙対策で、どの方法で登録したかは調べられないので本人に選んでもらう）
  - 前の方法でログインできて、メールアドレスが同じなら `linkWithCredential` で新しい方法をつなげ、「{provider} をつなげました」と出す。以後はどちらの方法でも同じアカウント（同じ uid・同じデータ）に入れる。メールアドレスが違えばつながずにそのままログインし、その旨を出す
  - ポップアップを閉じたときは覚えたまま。メニューを閉じる・ページを離れると捨てる（保存しない）
- 文は `js/i18n.js`（`account.*`）、見た目は `css/common.css`

## プライバシーポリシーとデータの削除（`privacy.html`・`js/privacy.js`）
- 保存する情報には、練習の記録（タイム・日時・ケース・判定、ソルブのスクランブルとペナルティ）と練習の設定も含める。ブラウザへの保存の項には、ログイン中にアカウントの名前・メールアドレス・写真の URL・ログイン方法をブラウザに覚えること（ログアウトで消す）を書く
- 本文は日本語・英語の両方を HTML に書き、言語の切り替えに合わせて片方を出す（ログインで受け取る情報・保存する情報・使い方・保存先・削除の方法・問い合わせ先＝GitHub の Issues。運営は roudai.net）
- ナビバーのログインのメニューからリンクする：ログイン前は「ログイン」ボタンのメニュー、ログイン中はアイコンのメニューの「プライバシーポリシー」（データの削除はページの一番下）。Facebook のアプリの「プライバシーポリシーの URL」「データ削除の手順の URL」にこのページを登録する
- 「アカウントのデータを削除」（ログイン中だけ押せる）：押すと確認の文と「削除する」「キャンセル」を出し、「削除する」で削除する（ブラウザの確認ダイアログは使わない）
  - `CloudSync.deleteAccount()`：`users/{uid}/apps` の下の全アプリの文書を消し、ログインのアカウントも消す。しばらく前にログインした場合は Firebase が再ログインを求めるので、ログインしたときと同じサービスでもう一度ログインしてもらってから消す
  - ブラウザに保存された設定は残す（この端末とアカウントの結び付き `synced-uid`・アイコンの情報 `account-hint` は消す）
- `firestore.rules`：本人は自分の文書を削除できる（`allow delete`）

## 使い方（`guide.html`）
- サイトの使い方（エディタ・PLL / OLL・練習・記録・保存とログイン・問い合わせ）を日本語・英語で書いたページ（言語の切り替えは `js/legal.js`。画像は入れず文章だけ）
  - 称号の具体的な名前（最初・最後の称号を含む）は書かない（ネタバレになるため）。バッジの名前も書かない
  - 保存とログインの項に、保存できる記録の量（PLL・OLL はそれぞれ最新 10000 件、ケースごとの最近のタイムは各 10 回、ソルブは最新 2000 件。超えると古いものから消え、累計・称号・バッジは減らない）を書く（利用規約と同じ数）
- ログインのメニュー（ログイン前・ログイン中とも）の区切り線のすぐ下、「プライバシーポリシー」の上に「使い方」

## Firebase の設定手順（サイトの管理者がやる）
1. https://console.firebase.google.com/ でプロジェクトを作成（無料の Spark プランでよい）。ほかのアプリと共通にするので、名前・ID はアプリ名ではなく全体の名前にする（ID はログインのポップアップに出て、あとから変えられない）
2. 「プロジェクトの設定」→「マイアプリ」でウェブアプリを追加し（SDK は「script タグを使用する」、Firebase Hosting は使わない）、表示される `firebaseConfig` の中身を `js/firebase-config.js` の `window.FIREBASE_CONFIG` に貼る。ほかのアプリは同じプロジェクトにウェブアプリをもう1つ登録する
3. Authentication → ログイン方法
   - Google を有効にする
   - GitHub を有効にする：GitHub の Settings → Developer settings → OAuth Apps で新しいアプリを作り、Authorization callback URL に Firebase の画面に出る URL（`https://<project-id>.firebaseapp.com/__/auth/handler`）を入れる。発行された Client ID / Client Secret を Firebase に登録する
   - 「設定」→「ユーザー アカウントのリンク」は **同じメールアドレスを使用するアカウントをリンク**（既定）のままにする（上の「ログイン方法をつなげる」はこの設定が前提）
   - Facebook を有効にする：https://developers.facebook.com/ でアプリを作り（ユースケースは「Facebook ログインでユーザーを認証」）、アプリ ID / app secret を Firebase に登録する。Facebook ログインの設定の「有効な OAuth リダイレクト URI」に Firebase の画面に出る URL（`https://<project-id>.firebaseapp.com/__/auth/handler`）を入れる。一般の人がログインできるようにするにはアプリを「ライブ」にする（プライバシーポリシーの URL などが必要）
4. Authentication → 設定 → 承認済みドメインに `roudai.github.io` を追加（`localhost` は最初から入っている）
5. Firestore Database を作成し、「ルール」にリポジトリの `firestore.rules` の内容を貼って公開する

## 公開するときにやること（未対応）
GitHub Pages（master）に公開するときに、あわせて次を行う。Facebook のアプリは今は開発モードなので、このままでは管理者・テスター以外は Facebook でログインできない。
1. Facebook アプリ → 「アプリの設定」→「ベーシック」
   - アプリドメイン：`roudai.github.io`
   - プライバシーポリシーの URL：`https://roudai.github.io/MegaminxImageEditor/privacy`
   - ユーザーデータの削除：「データ削除の手順の URL」に `https://roudai.github.io/MegaminxImageEditor/privacy#delete`
   - 利用規約の URL（任意）：`https://roudai.github.io/MegaminxImageEditor/terms`
   - アプリアイコン（1024×1024）・カテゴリ・連絡先メールアドレス
   - 「プラットフォームを追加」→ ウェブサイト：`https://roudai.github.io/MegaminxImageEditor/`
2. 左のメニューの「公開」から、アプリをライブにする（`public_profile`・`email` だけなので、ふつうはアプリレビューは不要）
3. 管理者ではない Facebook アカウントで、公開中のサイトからログインできるか確かめる
4. Firebase の承認済みドメインに `roudai.github.io` があるか、Firestore のルールが最新か確かめる
